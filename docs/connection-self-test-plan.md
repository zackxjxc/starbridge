# 本机连接测试方案

日期：2026-10-26。状态：已实施并通过 Windows 客户端经公网 FRPS 的真实回连、SSH 和清理验收；不外推为 macOS 或任意网络环境均已通过。最终两栏布局、精简说明、系统专属入口和测试状态展示遵循 [客户端 UI 与交互定稿](client-ui-and-interaction-spec.md)；普通会话准入遵循 [客户端交互与会话占用规则](client-experience-and-session-rules.md)。

登录成功后，用户可以点击“连接测试”。同一台电脑同时运行 SSH 发起端和 SSHD 接收端，通过远程 FRPS 中转完成一次真实 SSH 登录与数据交换，提前发现本机组件、网络或安全软件造成的运行问题。默认测试无需另一台用户设备，也无需额外部署 SSH 测试节点。

## 测试目标与覆盖范围

测试使用正式发布的 FRP 和 OpenSSH 组件，执行正常业务会发生的组件启动、隧道建立、身份校验、登录和少量数据传输。安全提示可能在这些操作中出现；测试成功以真实连接完成为依据，不以是否出现弹窗为依据。

| 检查项 | 默认测试能够验证的内容 |
| --- | --- |
| 运行时组件 | SSH、SSHD、FRP 及本次操作涉及的子组件能否从实际运行时目录启动和持续运行 |
| 服务器通信 | 本机到当前远程 FRPS 的连接、认证、代理注册和中转数据传输 |
| SSH 发起能力 | SSH 客户端通过本地 visitor 端口建立连接，校验主机身份并完成公钥登录 |
| SSH 接收能力 | 本机 SSHD 接受 FRP 转发的连接，完成鉴权、启动测试会话并返回固定测试结果 |
| 运行环境 | 当前系统账户、权限、组件版本、程序路径和网络条件下，上述操作是否成功 |

默认测试不验证跨设备 XTCP 直连。另一台设备的 NAT、UDP 策略、安全软件和 SSH 配置，仍须在实际双方连接时验证。测试通过只代表本次路径与操作可用，不能保证后续安全策略、版本或网络变化后仍然可用。

内置 SSHD 测试使用隔离的临时密钥与配置，证明正式组件在当前环境下能够完成测试流程。正式存量主机密钥、`authorized_keys` 和业务配置是否正确，仍由真实业务会话检查，不随测试实例通过而视为已验证。

SFTP 文件传输作为后续可选检查：只在测试专用目录上传、下载一个小文件并校验内容，不接触用户文件。未执行时明确显示“文件传输未测试”，不因 SSH 登录成功而宣称文件传输通过。

## 用户入口与交互

在登录后双栏主界面的左栏本机区域和默认本机页提供“连接测试”入口，并显示最近测试状态。默认一次检查 SSH 发起和 SSHD 接收两种能力，用户无需选择永久的控制端或执行端身份。进度与结果在右栏呈现，不增加服务器地址、FRP 配置等普通用户输入项。

用户点击入口后先阅读说明，再点击“开始测试”。登录成功和登录恢复都不自动执行完整测试。

说明页使用 [最终交互定稿](client-ui-and-interaction-spec.md#连接测试) 中的精简文案：

> 检查这台电脑是否可以正常发起和接收连接。
>
> 连接组件与安全软件提示中说明官方组件来源、可能的误报和防火墙放行；提示风险时先核对来源与文件校验结果。仅 Windows 显示「Windows 处理方法」。内部测试拓扑不放进开始前说明，按需在结果与技术详情中查看。

说明页提供“开始测试”和“取消”；运行中提供“取消测试”和“查看详情”；结束后提供“重新测试”和“查看详情”。用户处理安全提示时可以查看当前状态；达到超时后清理本次资源，用户处理完成后再重试，不无限等待。

同一设备同时只能有一个测试。首次实施仅允许空闲设备启动完整测试；已有普通会话或批量连接任务时提示先结束相关任务，不自动断开。测试期间拒绝新的普通建联请求，测试结束后释放临时占用，避免测试与业务争用组件和端口。

如果设备或服务端策略禁止中转，则不执行此项中转测试，显示“当前策略不允许中转测试，尚未验证”。测试不得自动改写“本机只允许直连”等偏好，也不得把跳过当成通过。

## 同机中转路径

```mermaid
flowchart LR
    A[本机 SSH 客户端] --> B[本机 frpc 访问端]
    B --> C[远程 frps]
    C --> D[本机 frpc 提供端]
    D --> E[本机 SSHD 测试实例]
```

这里的访问端与提供端是 FRP 的两个角色，可由受管的独立配置或实例承载，不需要启动两套完整 StarBridge 客户端。

测试固定使用 STCP，跳过 XTCP，禁止通过本地快捷路径完成。SSH 必须连接测试 visitor 端口，不能直接连接 SSHD 的回环端口。FRPS 使用正常业务下发的远程入口，不为测试在本机启动一个 FRPS。开发配置指向本地 FRPS 时，只能标记为“本地联调通过”，不能展示远程中转环境已通过。

当前内置 SSHD 只监听 `127.0.0.1`，远程 SSH 数据由 FRP 转发后接入。测试保持这一设计，不需要向公网开放本机 SSH 端口，也不安装系统 SSH 服务。

## 测试执行流程

1. **检查前提。**确认登录和设备身份有效，设备空闲，策略允许中转。检查实际运行时文件、数据目录权限与可用回环端口；组件缺失时报告具体文件，不临时下载替换运行时。
2. **申请诊断会话。**中心校验账户、设备身份和策略，原子检查并预占本机，签发带唯一测试 ID、路由名称和到期时间的诊断会话。它只允许当前设备承载两端角色，不能指定任意其他设备作为目标。
3. **准备临时 SSH 环境。**在当前数据目录的测试子目录生成临时客户端密钥、主机密钥和独立配置，启动受管 SSHD 测试实例。使用当前系统账户、正常权限和正式组件管理逻辑；测试授权不写入正式 `authorized_keys`。
4. **建立 FRP 中转。**使用同一正式 `frpc` 程序承载访问端和提供端，按测试 ID 绑定同一条 STCP 路由。等待两端就绪，再通过 visitor 端口发起真实 SSH 连接。
5. **验证 SSH 与数据。**客户端固定校验本次临时主机公钥，使用临时客户端密钥登录。测试实例执行固定回显动作，返回本次随机挑战值；同时检查 SSH 退出状态与返回内容，避免把旧结果或仅 TCP 连通当成成功。
6. **确认实际路径。**核对两端 STCP 配置、远程 FRPS 入口和测试 ID，关联服务端转发日志或测试路由流量记录，确认数据经过远程中转。无法确认时报告验证未完成，不只凭组件启动或代理注册成功宣称中转通过。
7. **清理并展示结果。**结束 SSH、撤销诊断路由和授权、停止测试子进程、关闭端口、移除临时密钥与配置，释放临时占用，然后保留脱敏结果供查看或重试。

所有阶段设置超时，并受单次测试的总期限约束。服务端拒绝诊断能力或客户端版本不匹配时，明确报告暂不支持，不通过注册虚假设备或放宽普通会话规则绕过。

## 与现有实现的衔接

目前 `ClientApp::load` 会调用 `prepare_ssh` 并启动内置 SSHD，早于登录和测试入口。实施时应拆分静态环境检查与外部组件按需启动：首次测试或首次真实连接启动组件之前先展示相应说明。能力上报同时区分“尚未初始化”和“检查失败”，避免尚未启动 SSHD 就被永久登记为不支持接收连接。

接收入站请求时，服务端与客户端需要支持初始化和就绪协商：尚未初始化但支持接收的设备可以进入准备阶段，目标初始化成功并回报真实就绪后再继续连接。初始化失败返回具体原因，不因尚未上报就绪而提前拒绝所有入站请求，也不把能力声明当成 SSH 已经可用。

普通 `create_session` 当前拒绝发起节点与目标节点相同的请求。保留这条普通业务限制，另设诊断会话类型与生命周期；客户端和服务端均明确区分普通会话与测试会话，不把测试路由放入设备列表、普通 SSH 命令复制或批量导出结果。

诊断预占必须与普通会话准入原子协调，防止“检查时空闲、启动时已被连接”的竞争。预占只影响本次本机测试，不创建长期虚假节点，也不改变普通设备的一对多、同向复用和占用释放规则。

测试复用正式组件的定位、启动、配置生成和日志采集逻辑，避免另写一套简化连接流程。组件必须保持相同的可执行文件路径、版本、父进程启动方式和权限，不复制到临时目录运行，不自动提权。临时数据与正式 SSH 配置隔离，沿用应用数据目录的权限保护。

如果当前配置使用外部 SSH 服务，则接收能力必须针对该服务验证。未取得可用的受限测试授权时显示“外部 SSH 服务接收能力未完成验证”，不能用内置测试 SSHD 的成功替代外部服务的结果。

## 授权与资源回收

SSH 私钥仅保留在本机受保护的测试目录，不上传中心。测试 SSHD 仅接受本次临时公钥与固定回显动作，限制交互式访问、端口转发等无关能力；服务端不能借诊断接口向用户设备下发任意命令。

诊断会话、代理名称与访问授权按测试 ID 隔离，使用短时有效期。服务端到期撤销必须落实到 FRP 路由或访问授权；仅把 HTTP 业务记录标记为过期，不算数据面授权已撤销。具体 FRP 接入校验与到期回收机制在实施时一并完成，不把会话密钥视为天然具备过期能力。

成功、失败、超时、取消、登出和窗口退出均进入同一幂等清理流程。取消后不再启动下一阶段；迟到的启动结果或网络响应只能回收资源，不能重建已结束的测试。只停止本次测试拥有的进程和路由，不触碰正式 SSHD、系统 SSH 服务或其他业务连接。

发生断网或中心不可达时，本机仍立即停止测试进程并清理私钥与临时授权；服务端依靠到期回收撤销残留路由与占用。下一次启动按测试 ID 清理遗留测试资源；重连后补报关闭状态。清理失败时显示“清理未完成”及可处理的原因，不直接展示整体测试成功。

测试不自动关闭防护、不修改安全软件排除项、不删除防火墙阻止规则，也不要求用户直接放行所有程序。普通详情只显示结果与处理建议；技术详情可以按需展示具体组件名称、绝对路径、阶段和错误摘要。

## 结果与故障诊断

结果按组件检查、FRP 中转、SSH 发起、SSHD 接收和资源清理分项展示，支持通过、失败、未完成和未测试。共享的上游步骤失败时，后续项目标记为“未完成，依赖步骤失败”，不推断其自身有故障。SSH 两端分项来自同一次连接，各自结合客户端与 SSHD 日志判断。

成功文案：

> 本机连接测试通过：SSH 发起、SSHD 接收、服务器中转均正常。跨设备直连将在实际连接时检查。

| 现象 | 结果与处理方向 |
| --- | --- |
| 运行时文件缺失或无法执行 | 显示组件、路径及系统错误；提示检查完整发布目录与安全软件隔离记录 |
| 进程启动后异常退出 | 显示退出码和日志摘要；原因未确认时保留待排查状态 |
| FRPS 不可达、认证或注册失败 | 区分网络连接、认证和路由注册阶段，不归类为 SSH 故障 |
| SSH 主机校验或公钥登录失败 | 显示 SSH 鉴权阶段及 SSHD 对应摘要，不以端口可连判断通过 |
| 超时或连接被重置 | 显示失败阶段和已收集证据，提示网络与安全策略排查，不直接认定杀毒拦截 |
| 有对应程序、时间和操作的明确拦截记录 | 标注已确认拦截，并提供人工处理后重试入口 |
| 无法取得安全产品记录 | 保留原始连接错误；可提示用户查看安全软件记录，不推断已被放行或已被拦截 |

Windows 防火墙可能因已有规则、通知设置、用户权限或企业策略而不弹窗。曾经拒绝后留下阻止规则时，重复测试也可能继续被阻止。通过真实测试和证据判断结果，不用“没有弹窗”推断环境正常。

日志至少记录测试 ID、阶段、时间、组件版本、实际路径类型、退出状态、错误摘要与清理状态。查看详情时可展示本机程序路径；导出前脱敏用户名、目录及设备信息，不包含私钥、密码、账户令牌、设备令牌或 FRP 密钥。

## 实施与验收

服务端诊断会话与到期回收、客户端受管测试流程与清理、界面入口与结果均已实施。本地 FRPS 测试仍只记为联调；2026-10-26 升级公网中心后，已另行使用正式 Windows 便携客户端，经 `168.110.58.38:17851` 执行真实回连和 SSH 验证。中心最终状态为 `succeeded`，`relay_verified=true`、`ssh_verified=true`、`cleanup_complete=true`、`local_relay=false`，另一次取消测试也清理成功。未调整系统安全配置；macOS、任意网络下的直连和实际防火墙弹窗不在此结论内。

另已验证运行中的客户端在生产服务重启后自动刷新凭据并完成公网测试，不需要用户再次输入密码。诊断请求仅在 401 时刷新并重试一次，退出或切换账号后禁止新建旧测试；已接受的测试保留原账号的有限清理路径，避免误用新账号凭据。

| 验收场景 | 预期结果 |
| --- | --- |
| 一台 Windows 电脑，无其他在线设备 | 登录后可经远程 FRPS 完成同机 SSH 与 SSHD 中转测试 |
| 中转成功 | 随机挑战值正确、SSH 正常退出、实际远程转发证据可关联，清理完成后才显示整体通过 |
| 检查到本地 FRPS 或允许 XTCP 的测试配置 | 不误报远程中转通过；默认测试配置固定为 STCP |
| 组件缺失、启动被阻止或运行中被终止 | 按阶段显示证据；无法确认时不标成已确认杀毒拦截 |
| FRPS 不可达、认证失败、SSH 鉴权失败或超时 | 保留对应失败结果，后续依赖项未完成，无残留测试访问能力 |
| 没有系统弹窗或已有阻止规则 | 照常以真实连接结果判断，提供人工排查与重试 |
| 中转被策略禁止 | 不执行，不改偏好，明确显示尚未验证 |
| 已有业务会话或同时发生普通连接请求 | 按原子准入只允许一方进入，不误断业务、不遗留占用 |
| 重复点击、任意阶段取消、登出或退出 | 同机最多一个测试，结束操作幂等，迟到响应不能重建资源 |
| 客户端崩溃、断网或服务器重启 | 本地遗留资源可恢复清理，服务端授权与占用到期回收，旧测试不能复活 |
| 清理遇到错误 | 明确显示未完成清理及原因，禁止把测试当作整体成功 |
| 使用外部 SSH 服务 | 接收项对应真实外部服务；无法受限验证时明确未完成，不以内置服务替代 |
| 设备列表、普通会话和复制导出 | 无虚假测试设备，无测试 SSH 命令混入业务结果，普通自连限制仍生效 |
