# macOS 发布检查清单

本轮在 Windows 完成 Rust、浏览器和打包回归。以下项目必须在 Mac 实机执行，浏览器中的 macOS 布局截图不能证明系统钥匙串、签名和原生窗口行为正确。

## 构建与固定签名

使用 Apple Silicon Mac，先同步 master，安装项目要求的 Rust 与运行时依赖，然后运行：

```sh
cargo test --workspace --locked
cargo build --workspace --release --locked
python3 tools/package_macos.py --help
```

按 `--help` 和运行时清单准备 arm64 运行时。正式包显式传入 `--signing-identity "Developer ID Application: 证书完整名称"`（或准确证书指纹），输出使用新的 `.app` 路径。默认 `-` 是 ad-hoc 签名；不要把未指定证书的包当成固定 Developer ID 升级验收。打包脚本会验证架构、签名和运行时文件。本流程不替代 Apple 公证流程。

## 独立资料与测试账号

使用专用测试账号和空目录启动，避免修改日常资料：

```sh
"/实际路径/StarBridge.app/Contents/MacOS/starbridge" --data-dir "$HOME/StarBridge-test/recovery"
```

确认实际 bundle 可执行文件名与 `Contents/Info.plist` 的 `CFBundleExecutable` 一致。不要复制日常默认档案到 `--data-dir`，这种混用会被拒绝。首次成功登录并记下设备名称和记录；每次修改测试文件前完全退出应用。不要在日常钥匙串条目或系统机器 UUID 上做破坏性测试。

## 实机用例与预期结果

| 场景 | 操作与预期 |
| --- | --- |
| 正常重启、更新 | 同一签名身份连续构建两个版本，使用同一测试目录升级。设备名称、记录和连接能力保持正常；启动和后台读写不自动弹授权框。 |
| 首次从旧 ad-hoc 包升级 | 保留旧测试包产生的凭据，再换正式签名包。若授权不足，显示系统访问恢复页；点击「授权后重试」才可触发系统弹窗。记录系统版本、签名和实际弹窗行为。 |
| 拒绝、取消、允许授权 | 在上述授权场景依次拒绝／取消：应留在页面，文件引用不变、不创建新设备。再次点击并允许后，应恢复原设备。系统要求 Mac 登录钥匙串密码，界面说明应准确。 |
| 仅登录缓存损坏／缺失项 | 仅在测试资料中损坏 `auth.secure` 的引用，或移除它准确指向的测试钥匙串项。下次启动直接显示登录页及缓存保留提示；重新登录后原设备记录不变，`recovery-backups` 保留旧缓存。 |
| 设备身份损坏／缺失项 | 仅损坏测试 `identity.secure` 引用，或移除它准确指向的测试钥匙串项。应显示账号验证恢复表单。错误密码不改动文件、不生成备份；正确密码一次输入即可恢复。机器键未变且原实例已退出时复用原记录。 |
| 活动实例冲突 | 通过两个独立测试实例和本项目的克隆／同记录测试准备冲突。正确密码后应出现新增／替换选择，不再索要密码；新增保留双方，替换结束旧实例连接。不要误替换日常设备。 |
| 识别状态损坏 | 损坏独立测试资料中的 `machine.json`，再次启动并验证账号。应保留原文件备份，新建设备记录且保留旧记录。身份引用与识别状态同时损坏也只需一次密码输入。 |
| 文件权限或配置损坏 | 让测试 `config.json` 无法解析。应显示本机数据错误及重试入口，不能直接重建设备。恢复文件后可重试。 |
| 钥匙串备份可用 | 在身份恢复前记录测试 `.secure` 中的引用。恢复后新引用应不同；旧引用对应的钥匙串项仍存在，不被新内容覆盖。备份目录权限应为 `0700`，不泄露引用或内容到截图和日志。 |
| 中英文与布局 | 中文、英文各检查授权页、账号恢复页、错误密码提示和实例选择；英文不残留中文错误。900×600 窗口所有按钮可访问，原生红黄绿按钮、44px 标题栏、拖动及系统深浅色显示正常。 |
| 关闭与连接 | 恢复页、授权弹窗和恢复进行中分别关闭／退出，应无卡死或额外身份生成；关闭到托盘、重新打开、退出清理正常。恢复后执行真实连接测试与 SSH 命令。 |

最后保存测试结果：macOS 版本、芯片架构、Git 提交、签名证书身份、旧／新包来源、各用例结果及异常。涉及钥匙串 ACL、系统弹窗和签名连续性的结果必须以实机观察为准。
