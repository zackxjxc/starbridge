# 设备身份与迁移

用户手动输入账号密码登录后，软件自动完成本机登记或恢复，不再要求第二次输入密码或另行绑定。设备 ID 标识服务器上的记录；设备凭据是软件自动保存、可撤销的长期本机登录凭证，用户无需管理。系统机器标识只用于在同账号下寻找原记录，不是认证凭据或不可伪造的硬件证明，也不保证绝对唯一。

## 机器查找键 v1

客户端使用固定版本 `machine-uid`：Windows 读取 MachineGuid，macOS 读取平台 UUID。原始值只在本次读取及派生时存在，不保存、上传、写日志或展示。

规范化契约在发布后保持不变：

1. 只去除首尾 ASCII 空白。
2. 接受一对完整外层大括号，也接受无大括号的值。
3. 内容必须是 32 个十六进制字符，或标准 `8-4-4-4-12` 格式；连字符只能位于该格式的固定位置。
4. 去掉格式分隔符，转换为 ASCII 小写，得到 32 个十六进制字符。
5. 拒绝空值、非十六进制字符、内部空白、不完整括号、全零和全 `f`。

原生机器查找键为 `SHA256(b"starbridge:machine:v1\0" + normalized_uid)` 的 64 位小写十六进制表示。固定命名空间用于应用内隔离；将来如需更改规范，必须另设版本并提供明确迁移流程。

服务器在已认证账号范围内按机器键查找设备，不跨账号合并。原有 `node_id` 继续作为连接协议和记录 ID。客户端按中心地址和账号保存独立凭据绑定，切换账号不会沿用另一账号的设备权限。

## 复用、重新绑定与删除

同账号、设备凭据匹配时优先复用准确的设备记录，保留名称、用途、协议 ID 和连接历史。同一机器键可以对应用户明确选择新增的多个设备，不能仅凭机器键或名称盲目合并。原凭据仍有效且没有其他活动实例时，重启或恢复快照直接继续使用，不因普通心跳和登录令牌续期轮换设备凭据。

本地数据丢失、重新安装或恢复快照导致凭据不一致时，手动密码登录授权本次恢复：若账号内只有一条对应记录，且没有确认存活的其他实例或活动任务，自动替换旧凭据并恢复使用。旧凭据保持撤销，不能由旧快照在后台抢回。机器键无法对应原记录时新增设备，保留原记录，不按名称或 IP 猜测身份。

后台恢复登录和心跳只有普通账号令牌与本机凭据，不拥有替换权限；凭据失效时结束本机连接、清理登录状态，提示重新登录。删除设备会持久保存撤销记录，旧后台客户端不能自行复活；用户再次手动密码登录可以自动重新添加，无需额外绑定步骤。

服务器为每次客户端启动分配独立实例租约。遇到其他实例时，等待四秒并检查等待期间的新登记或心跳活动，不能仅凭三十秒内的旧在线时间判定冲突。只有确认另一个实例仍活动、有连接或连接测试，或者多条记录无法准确判定时，才要求选择使用方式。

选择“作为另一台设备添加”会创建独立记录，保留双方；选择“替换原实例”会展示设备名称、活动连接数量和测试状态，用户确认后接管原记录、结束其连接并取消测试，旧实例随后退出。两种选择都复用本次密码验证，不再次索要密码。

新客户端使用 `POST /api/v1/devices/enroll`。密码只存在于当前手动登录请求，不写入凭据或保留到选择弹窗。需要选择时，服务端签发五分钟内有效的恢复许可，绑定账号、当前访问令牌、启动实例、本机识别键、请求凭据及可选择记录的凭据版本；许可只保存在双方内存中，不返回到普通界面状态。选择请求不能跨账号、跨实例或替换已变化的记录；相同选择的重试返回同一结果，新增设备不会重复创建。

查找、选择校验、撤销和持久化使用同一写锁；持久化失败恢复旧记录与租约。客户端在发送恢复前保存新的待确认凭据，服务器成功但响应丢失时，重启可用该凭据找回准确记录。旧版登记接口仍不自动替换凭据，也不能覆盖新客户端已持有的实例。

## 默认目录与独立联调

| 平台 | 默认当前用户目录 | 凭据存储 |
| --- | --- | --- |
| Windows | `%LOCALAPPDATA%/StarBridge` | 当前系统用户的 DPAPI；`identity.secure` 和 `auth.secure` 为受保护的载荷 |
| macOS | `~/Library/Application Support/StarBridge` | 系统登录钥匙串；`.secure` 文件仅存钥匙串引用 |
| Linux | 绝对路径的 `$XDG_DATA_HOME/StarBridge`，否则 `~/.local/share/StarBridge` | 当前预留实现使用 `0700` 目录及 `0600` 文件，需要后续平台验证和密钥存储增强 |

默认目录与程序路径无关。同一系统用户从不同解压目录启动会使用同一身份和进程锁；第二个实例会提示先退出原实例。不要在多台电脑间复制该目录，也不要把它打入发布 ZIP。

开发联调使用独立的显式目录，例如：

```powershell
starbridge.exe --headless --data-dir state/node-a
starbridge.exe --headless --data-dir state/node-b
```

不同目录各自生成并持久保存独立实例查找键，使用 `starbridge:instance:v1\0` 命名空间，不使用默认正式设备的原生机器键。重启仍沿用该目录的身份。每个目录有独立实例锁，显式目录不能指向默认用户目录。测试应选择空目录；将已有正式档案复制到显式目录后启动会被拒绝，避免误用正式设备的原生或降级查找键。保留正式身份应使用 `--import-data-dir` 导入空默认目录。将独立测试目录的完整身份复制到另一目录会复制同一身份，不能据此获得另一台独立设备。

## 旧数据迁移

默认目录尚无身份时，会检查程序旁和当前工作目录下的 `state/node`、`state/controller`、`state/executor`。只发现一个旧身份时自动导入，保留原 `node_id`、设备凭据、名称、用途、配置和 SSH 数据。身份与登录数据成功写入平台安全存储后，移除导入结果中的旧明文文件。原目录保留恢复副本，并写入 `migrated-to.json`，新客户端拒绝再次从该旧副本启动。

原目录和自行保存的迁移备份仍可能含旧明文设备凭据及登录数据，应按敏感数据保管，不得分享或放入发布 ZIP。无法确定账号归属的旧身份会作为待确认候选保留；首次登录另一个账号不会将它直接据为己有，只有原账号与原设备凭据验证通过后才会绑定或迁移。

发现多个旧身份时停止自动迁移，不选择其中一个覆盖其他身份。退出旧客户端并备份各旧目录后，明确选择要保留的目录：

```powershell
starbridge.exe --import-data-dir "D:\old\state\controller"
```

该参数只允许导入到尚无设备身份的默认目录，不能与 `--data-dir` 同用，不能覆盖已有默认身份。已存在默认身份时，先核对并备份；确需改选另一旧身份时，应退出客户端，移走现有默认数据目录后再明确导入。不要手动拼接多个身份文件或删除来源不明的旧目录。

导入已有新版独立实例目录时，会保留它已经持久化的查找键与来源，避免迁移时静默切换业务身份。服务端重复记录仍需通过设备列表明确处理。

## 读取失败、来源变化与克隆冲突

`machine.json` 只保存派生键、来源及版本。首次原生读取失败、为空或无效时，生成一次随机降级标识，使用 `starbridge:fallback:v1\0` 命名空间派生后持久保存。以后重启不重新随机；原生读取恢复后也不自动切换。

已经采用原生来源时，临时读取失败仍沿用保存的键。如果后来成功读取到不同的原生值，客户端停止使用该档案并给出处理提示，避免默默替换设备。Windows 全新重装可能产生这种情况。应保留数据、恢复原环境或从新的独立 `--data-dir` 登记，再明确处理旧记录；不得删除身份文件来绕过冲突。

克隆系统可能复制机器标识乃至设备凭据。每次启动生成新的内存实例标识；同时运行且对应同一记录时，通过存活核验与新增／替换选择处理，用户无需手动配置独立目录。完全克隆仍不能证明两台系统的物理身份；离线且无法区分的副本按同一逻辑设备恢复处理。本方案不增加额外硬件指纹。

普通设备界面和复制文本只用名称、用途、系统及在线状态识别设备，不展示原始机器标识、机器键、设备凭据或内部记录 ID。连接协议仍保留必要 ID 和 SSH 别名。打包脚本只复制允许的程序、运行时和许可证文件，拒绝覆盖含使用过身份数据的输出目录。

## 平台验证范围

本次开发环境为 Windows。原生读取、DPAPI、目录锁及 Rust 回归可在当前环境运行；前端重新绑定流程使用隔离测试后端验证，打包使用虚拟运行时夹具验证。macOS 原生读取、钥匙串权限与系统交互，以及 Linux 文件权限、机器读取和桌面行为，仍需要相应系统实机验收，不能以跨平台代码存在代替验证。
