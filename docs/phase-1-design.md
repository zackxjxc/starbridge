# 一期详细设计：中心服务器远程组网

## 目标和边界

一期提供一个中心服务器版本。节点登录中心服务器后可以互相建立 SSH、SFTP 或 SCP 通道。连接优先使用 FRP XTCP 直连，直连失败时按策略使用 FRPS 中继；用户能看到最终路径。中心服务器和 FRP 都可以先在开发机运行，完成测试后再部署到 Linux 服务器。

一期不实现离线局域网发现、虚拟机专用通道、远程开关机、桌面控制和 Electron/Tauri/Flutter 外壳。它们记录在 [future-roadmap.md](future-roadmap.md)，进入开发前需要重新评审。

## 进程模型

中心服务器只需要一个 `starbridge-server` 和一个 `frps`。StarBridge 不为每一对节点启动独立 frps，也不通过 CLI 逐连接启动新的 frps；frps 本身支持多节点、多会话和中继。

每台设备只需要一个 StarBridge 核心进程，由核心按会话管理 frpc 子进程。核心通过本机回环 API、配置文件或受控子进程接口驱动 frpc，生成带会话随机数的 XTCP/STCP 路由配置并执行幂等的启动、替换和停止操作。SSH 客户端仍是独立进程，连接核心为本次会话分配的本地 visitor 端口。

## 连接策略

每次连接在发送请求前选择以下策略之一：

| 策略 | 行为 |
| --- | --- |
| `direct_preferred` | 先尝试 XTCP 直连，失败后使用 FRPS 中继 |
| `direct_only` | 只尝试直连，失败即失败，不建立中继 |
| `relay_only` | 跳过直连，直接使用 FRPS 中继 |

设备属性中的“本机只允许直连”会把该设备作为发起端或目标端时的有效策略限制为 `direct_only`。只要任一端禁止中继，系统不得在直连失败后偷偷回退到中继。服务端应在会话状态和审计日志中记录最终策略及原因。

## 一次建联流程

1. 用户启动 StarBridge；默认打开 Tauri 设备中心窗口，无界面模式保留本地 HTTP 控制台。
2. 用户填写中心 URL、账户名称和密码，可选择记住身份。核心通过 HTTPS 登录，保存短期访问令牌和可撤销刷新令牌。
3. 核心登记稳定的 `node_id`、可编辑的显示名称、SSH 能力、在线状态和本机直连策略；密码不以明文写入本地配置。
4. 控制台显示已登录节点。用户打开连接对话框，选择目标节点和本次连接策略。
5. 中心 StarBridge 根据设备令牌确认发起节点，校验双方账户、在线状态、实际 SSH 能力和策略，创建带 `session_id`、版本号、过期时间和一次性随机数的会话。
6. 两端核心分别令各自的 frpc 应用本次路由配置，frpc 连接中心 `frps`。不会为本次会话启动新的 frps。
7. FRP 先按策略协商 XTCP 直连。成功后状态为“直连”；若失败且策略为 `direct_preferred`，转入 FRPS 中继并显示“中转”。
8. 发起设备创建本地 visitor 端口，UI 提供本次会话的 SSH 命令。SSH 只连接本机 visitor 端口，目标设备的 frpc 再连接其内置 sshd 的回环端口（23000-23999）。每台设备以当前用户权限启动内置 sshd，只接受同账户设备的公钥；SSH 配置和固定的目标主机公钥按会话隔离。双方都可以再次发起反向会话，两条会话独立运行和断开。
9. 任意端心跳、frpc 状态或本地 SSH 检查失败时，中心和两端更新会话状态，UI 提示具体是本机组件、目标设备、直连协商、FRPS 或 SSH 服务故障。
10. 用户断开连接时，两端撤销路由、关闭 visitor 和临时配置，服务端将会话标记为结束。

## 节点和权限模型

节点记录至少包含：`node_id`、显示名称、稳定 SSH 别名、账户归属、在线状态、最后心跳、SSH/SFTP/SCP 能力、是否允许中继、支持的传输方式和版本信息。显示名称可以随时修改，但 `node_id` 和 SSH 别名保持稳定，避免复制给 AI 的文本失效。

复制功能包括“复制当前节点”和“复制全部可连接设备”。默认只复制当前账户有权使用且在线的节点，也可以在 UI 中选择包括离线节点。复制给 AI 的文本只包含节点名称、SSH 别名、在线状态、能力和可执行命令，不包含 StarBridge URL、FRP 地址、账户密码、访问令牌或私钥。

## 端侧 UI

首次打开显示中心 URL、账户名称、账户密码和“记住身份”选项。登录后显示节点卡片、在线/离线状态、能力和上次连接路径。

连接对话框必须在建联前显示“优先直连并允许中继”“只允许直连”“直接使用中转”三个选项；建联后显示“直连协商中”“直连”“中转”“失败”等状态及断线原因。设备属性页提供显示名称、SSH 别名、本机只允许直连和是否允许被控制等设置。

连接成功后可以打开本地 SSH 命令行窗口，也可以只复制命令。另提供一键复制全部可连接设备信息给 AI 的按钮。

如果本机 frpc 启动失败，UI 除了显示进程退出码和日志摘要，还应提示用户检查杀毒软件、Windows Defender 或企业安全策略，并提醒用户手动放行对应 FRP 文件或将安装目录加入白名单。提示必须说明这是用户手动确认的系统安全操作，StarBridge 不自动关闭防护或修改白名单。

## 中心管理 UI

管理页面固定为 `https://starbridge.zackxjxc.de5.net/admin`，通过中心 StarBridge 的管理 API 展示账户、节点、会话、最终传输路径、frps 在线状态、失败原因和审计日志。管理 UI 不直接修改 frps 内部状态；需要调整路由时由中心服务生成受版本控制的策略并通知端侧核心。

## 二进制依赖

FRP 与 OpenSSH 的来源、版本锁定、下载、校验和发布目录见 [dependencies-and-packaging.md](dependencies-and-packaging.md)。构建流程在发布前准备依赖，不允许运行中的客户端随意从互联网下载可执行文件。

## 安全和可观测性

中心服务使用 HTTPS/WSS；frpc 与 frps 使用 FRP 的认证和 TLS 配置。账户密码只用于登录交换令牌，刷新令牌放在系统凭据存储或权限受限文件中。会话令牌、一次性随机数、过期时间和节点授权必须在服务端校验。

所有会话记录 `session_id`、发起端、目标端、策略、实际路径、开始/结束时间和失败原因。日志不记录密码、私钥和完整访问令牌。

Windows 杀毒软件对 FRP 的误报属于一期已知环境问题。我们保留 FRP 方案，暂不因误报引入替代网络组件；产品层只负责给出清晰的人工排查和放行指引。

## 开发和上线验收

先在 Windows 开发机上运行中心服务、frps 和至少两个端侧实例，覆盖中转、直连、回退、direct-only、relay-only、断线和 SSH/SFTP/SCP。再将相同版本和相同配置迁移到 Ubuntu ARM64 服务器，配置 nginx 的 443 入口、FRPS 的 17851 入口，并保持 17850 只监听回环地址。

## 兼容性

设备级 `role` 仅为旧登记数据和启动参数保留，不再参与连接权限判断。会话改用 `initiator_node_id` 标识发起设备，加载历史状态时兼容 `controller_node_id`。新客户端和中心服务应同步升级。
