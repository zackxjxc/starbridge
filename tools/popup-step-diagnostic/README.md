# 弹窗逐步诊断（临时工具）

需要 Windows、Python 3.10+，以及本仓库已构建的 `target/release/starbridge-client.exe`（desktop 版本）、`starbridge-server.exe` 和完整 `state/runtime`。不需管理员权限。不修改正式客户端源码。

1. 双击本目录的 **Start.pyw**。若 `.pyw` 未关联 Python，在仓库根目录运行 `python tools/popup-step-diagnostic/diagnostic.py`。仅打开本地浏览器诊断页，组件等待点击启动。
2. 点击 **下一步**，每步静置观察 10–20 秒。版本检查的进程通常很快退出。未登录窗口不要输入真实账号。
3. 弹窗出现后，先点 **刚才出现弹窗**，停止推进。可重复标记，再点 **结束并清理**。
4. 如前面没有出现，继续本地中心、两个临时节点、临时注册/登录、GUI 恢复步骤。最后按顺序记录并手动执行连接、终止连接、连接测试；测试要求本机空闲。每次先点下一步记录时间，再到测试客户端执行对应动作，回来观察。登录和恢复会启动客户端自有后台组件，不能把这些内部动作进一步拆开。
5. 用 **导出诊断报告** 下载 JSON。正常结束后本地服务退出，导出链接也停止；此时直接打开页面显示的输出目录里的 `report.json`。**只分享 report.json；不要分享 private-state-do-not-share**，其中有临时身份、密钥和登录凭据。

工具只绑定 127.0.0.1，随机分配端口，清除继承的 `STARBRIDGE_*` 环境配置，复制 runtime 和两个可执行文件到每次独立目录，不读取原有客户端账户。桌面可执行文件沿用分发包的 `starbridge.exe` 名称；报告记录组件 SHA-256 和大小，便于比对版本。版本检查只跑 `--version` / `-V`。临时中心的 HTTP 与 FRPS 均显式绑定回环地址。客户端自有 SSH 服务的绑定行为仍由现有组件决定；工具不改防火墙，临时账户仅存在本地中心。

进程每秒采样一次，记录诊断开始后新出现的进程 PID / 父 PID / 路径 / 启动时间（访问受限时路径为空）；不采集命令行、环境、键盘、截图。不会尝试捕捉弹窗文字或自动关闭弹窗。组件 stdout/stderr 丢弃，避免意外记录密码/token。报告仍含本机用户名路径和无关新进程名称，分享前可人工检查。

每个组件先挂起创建，加入独立 Windows Job Object 后再恢复；使用仓库现有 `tools/test-peer-connectivity.py` 中的 Job Object 实现。正常结束、Ctrl+C、页面停止心跳 60 秒后或 Python 进程退出时，仅结束工具拥有的进程树，不按名称杀进程，不结束已有客户端。浏览器后台休眠也可能导致超时，诊断时保持本页打开。强制结束解释器时可能没有最终 finished 记录，但 Windows 会关闭 Job Object。异常后目录保留，不自动删除，手动检查后可删除该次输出目录。

报告中的时间相关性不能证明因果；一秒采样可能漏掉极短进程。SSHD `-V` 的退出码差异属于版本探测结果，不表示真实服务已经启动。跳过依赖步骤可能令后续步骤失败（错误记录不包含敏感响应正文）。本工具不更改注册表、不安装 Game Bar、不主动调用 `ms-gamingoverlay` 或 Win+G，也不构造该问题的触发器。

无 UI 自测：`python tools/popup-step-diagnostic/selftest.py`。它只测试页面服务、动作记录、进程元数据采样及工具管理的 Python 子进程清理，不启动 StarBridge GUI、不操作真实账号。
